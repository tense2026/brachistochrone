# 변인별 최적강하선 비교 — 영향이 더 드러나는 환경

고전 사이클로이드를 초기값으로 두고, 유한 반지름·마찰·공기저항·회전·마그누스가 작용하는
환경에서 각 조건에 맞는 더 빠른 경로를 수치 탐색한 계산 실험입니다.

**검증 상태:** 아래 모든 수치는 이 저장소의 코드로 재실행해 `variable_results/`의 CSV와
바이트 단위로 일치함을 확인했습니다. 테스트 21개 전부 통과. 자세한 내용은
[재현 및 감사 결과](#재현-및-감사-결과) 참고.

## 바로 결과 보기

```bash
pip install -r requirements.txt
# 모든 조건을 합친 실제 저장 결과를 Gymnasium 재생 창에서 보기
python brachistochrone.py --replay-only --output-dir variable_results/06_all
# 공기저항만 있는 조건의 저장 결과
python brachistochrone.py --replay-only --output-dir variable_results/03_drag
```

재생 창은 GUI가 필요합니다. 화면이 없는 서버/컨테이너에서는 `MPLBACKEND=Agg`와
`--no-show`를 쓰고 PNG/CSV 산출물로 확인하세요. → [Docker로 재현하기](#docker로-재현하기)

## 전체 실험 재실행

```bash
python variable_study.py
# ZIP/저장소에 포함된 결과와 완전히 같은 설정 (seed=42)
python variable_study.py --episodes 180 --pop-size 20 --height 5 --length 10 --no-show
# 학습 도중에도 최선 경로 표시
python variable_study.py --visualize
# 작은 트랙으로 되돌리기
python variable_study.py --height 0.5 --length 1 --output-dir small_results
```

새 실험의 기본 진입점은 `variable_study.py`입니다. 기존 `python brachistochrone.py` 단독
실행은 이전 실험 조건(H=0.5m, L=1.0m, m=50g, R=15mm, mu=0.2, k=0.4)을 유지하므로
혼동하지 마세요. 새 스크립트 기본은 200세대/모집단20이며, 저장된 실제 실행 결과는
180세대/모집단20/seed42입니다.

## 달라진 환경

- 출발 높이 H=5m, 수평 거리 L=10m: **작은 3D 프린팅 장치가 아니라 효과를 관찰하기 위한
  큰 시뮬레이션 트랙**입니다.
- 질량 2.7g, 공력 반지름 2cm: 탁구공에 가까운 가벼운 속 빈 공의 예시입니다.
- 관성모멘트 계수 k=2/3. 공기 밀도 1.2kg/m³, 항력계수 0.47, 중력 10m/s².
- 공기 밀도나 양력 계수를 임의로 키우지 않았습니다. 면적/질량비와 이동 거리를 늘려
  저항이 누적되게 했습니다.
- 이전보다 절대 시간 차이가 커지는 데에는 트랙 길이에 따른 전체 시간 증가도
  기여합니다. 반드시 개선율(%)도 함께 제시하세요.

### 조건별 실제 파라미터

**마찰계수는 조건마다 다릅니다.** mu=0.15는 전체 결합 조건(`06_all`)과 마찰 단독
조건(`02_friction`)에만 적용되며, 나머지 조건은 변인을 분리하기 위해 mu=0 또는
수치적 이상값 mu=100을 씁니다. 아래 값은 `variable_study.py`의 `CASES`와
`variable_results/case_parameters.json`에 그대로 있습니다.

| 조건 | R(m) | track_radius(m) | mu | 회전 | 항력 | 마그누스 | omega0(rad/s) |
|---|---:|---:|---:|:---:|:---:|:---:|---:|
| `00_ideal` | 0 | 0 | 0 | ✗ | ✗ | ✗ | 0 |
| `01_radius` | 0.02 | 0.02 | 0 | ✗ | ✗ | ✗ | 0 |
| `02_friction` | 0 | 0 | 0.15 | ✗ | ✗ | ✗ | 0 |
| `03_drag` | 0.02 | 0 | 0 | ✗ | ✓ | ✗ | 0 |
| `04_rotation` | 0.02 | 0 | 100 | ✓ | ✗ | ✗ | 0 |
| `05_magnus` | 0.02 | 0 | 0 | ✓ | ✗ | ✓ | −100 |
| `06_all` | 0.02 | 0.02 | 0.15 | ✓ | ✓ | ✓ | 0 |

공통: k=2/3, 질량 2.7g, H=5m, L=10m, 구간 30개, physics_dt=0.01s, seed=42.

변인을 단독으로 정의하려면 공력 면적(`R`)과 기하학적 곡률 보정(`track_radius`)을
분리해야 하므로 두 인자를 따로 둡니다. 완전히 독립된 실제 물체를 의미하는 것이 아니라
효과를 분해하는 계산 실험입니다.

## 그래프 구성 (`variable_results` 폴더)

1. `00_ideal.png`: 이상 조건의 기준.
2. `01_radius.png`: 반지름의 곡률/접촉 보정만 적용. 항력/마찰/회전은 끔.
3. `02_friction.png`: 비회전 미끄러짐 마찰만 적용.
4. `03_drag.png`: 공기 항력만 적용. 공력 면적은 두되 유한 반지름의 곡률 보정은 끔.
5. `04_rotation.png`: 에너지 소모 없는 순수 굴림 한계. 큰 정지마찰 한계(mu=100)는 실제
   표면값이 아니라 미끄러짐을 방지하기 위한 수치적 이상 조건입니다. 정지마찰은 에너지를
   소모하지 않습니다.
6. `05_magnus.png`: 마그누스만 적용. 초기 omega=−100rad/s인 자유회전, 접선 마찰/항력 없음.
7. `06_all.png`: 유한 반지름·항력·회전·마찰·마그누스 전체 결합.
8. `combined.png`: 위 모든 경우의 곡선을 한 그림에 겹침. 오른쪽은 사이클로이드와의 실제
   높이 차이(m)입니다. 효과를 과장하는 정규화/임의 확대는 없습니다.

각 개별 그림은 해당 조건의 학습 곡선과 고전 사이클로이드를 비교합니다. 별도
`*_coordinates.csv`에 좌표가 있습니다. 모든 조건에서 동일한 출발/도착점, 질량, 격자,
시드를 씁니다.

## 실제 계산 결과

같은 물리 조건 안에서 고전 사이클로이드와 해당 조건에 맞게 탐색한 경로를 비교했습니다.
전체 표는 `variable_results/summary.csv`에 있습니다.

| 조건 | 사이클로이드(s) | 탐색 경로(s) | 차이(s) | 개선율 |
|---|---:|---:|---:|---:|
| `00_ideal` | 1.790147 | 1.789664 | 0.000482 | 0.027% |
| `01_radius` | 1.790147 | 1.789664 | 0.000482 | 0.027% |
| `02_friction` | 2.031000 | 2.028998 | 0.002002 | 0.099% |
| `03_drag` | 2.611387 | 2.487260 | 0.124127 | 4.753% |
| `04_rotation` | 2.311070 | 2.310447 | 0.000623 | 0.027% |
| `05_magnus` | 1.790147 | 1.789664 | 0.000482 | 0.027% |
| `06_all` | 2.935375 | 2.820254 | 0.115121 | 3.922% |

의미 있는 경로 개선이 나타나는 조건은 **공기저항이 들어간 경우뿐**입니다(`03_drag` 4.75%,
`06_all` 3.92%). 나머지 조건의 0.027%는 아래에서 설명하는 격자 오차 수준입니다.

시간 간격을 0.01→0.005→0.0025초로 줄여 같은 전체 조건 경로를 재평가했을 때 시간 차이는
0.115121→0.114494→0.114178초로 유지됐습니다. 경로를 다시 학습한 값은 아닙니다. 시간 간격
민감도에 비해 큰 개선이지만, 공간 격자 수렴/여러 시드/실제 장치 검증까지 마친 물리적
최적해 증명은 아닙니다.

**이상 조건에서도 약 0.00048초 사이클로이드보다 빠르다는 출력은 유한 격자/수치 최적화의
오차 효과입니다. 수학적 사이클로이드 정리를 반박하지 않습니다.**

### 왜 `01_radius`와 `05_magnus`가 이상 조건과 정확히 겹치는가

세 조건의 탐색 시간은 유효숫자 전부가 같습니다(1.7896644098784573s). 이것은 우연이나
탐색 실패가 아니라 **모델 구조상 필연**입니다.

- 두 조건 모두 **mu=0이고 항력이 꺼져 있습니다.** 이 모델에서 수직항력 N은 마찰력(mu·N)과
  항력을 통해서만 접선 방향 가속도에 들어갑니다. 둘 다 0이면 가속도는
  `a = g·sinθ`로 N과 완전히 무관해집니다.
- `01_radius`의 곡률 보정(`track_radius`)은 N을 바꾸지만, N이 접선 운동에 영향을 주지
  않으므로 시간에 전혀 반영되지 않습니다.
- `05_magnus`의 마그누스 양력도 N을 바꿀 뿐입니다. 접선 마찰이 없어 회전 토크가 0이므로
  omega가 −100rad/s로 일정하게 유지되고, 초기 회전 에너지는 접선 운동에 전달되지 않습니다.
- 따라서 **이 두 조건은 단독으로는 낙하 시간에 영향을 줄 수 없는 설정**입니다. "반지름과
  마그누스가 물리적으로 무의미하다"는 결론이 아니라, 변인을 단독 분리한 이 구성에서는
  효과가 나타날 경로가 없다는 뜻입니다. 두 효과는 마찰·항력과 결합될 때만
  관찰됩니다(`06_all`).
- `04_rotation`은 이상 곡선 모양을 유지하며 시간이 정확히 √(1+k)배가 됩니다. 실제로
  2.310446818/1.789664410 = 1.2909944487이고 √(5/3) = 1.2909944487로 1e−14 수준까지
  일치합니다. 그래서 개선율도 이상 조건과 같은 0.027%입니다.

억지로 차이를 만들지 않았습니다. 이 네 조건이 같은 개선율을 보이는 것이 모델이
일관되게 동작한다는 증거입니다. (`test_project.py`의
`test_radius_only_case_is_dynamically_inert`,
`test_pure_rolling_scales_time_by_sqrt_one_plus_k`가 이 두 성질을 고정합니다.)

## 수치 적분 방식 (RESEARCH_PLAN과 다른 점)

`RESEARCH_PLAN_ORIGINAL.md`는 구간별 등가속도 공식
`Δt = 2Δs/(v_i + v_{i+1})`로 시간을 더하는 방식을 기술합니다. 그 코드 경로는
`brachistochrone.py`의 `simulate_physics`에 남아 있고 `python brachistochrone.py` 단독
실행과 일부 테스트가 씁니다.

그러나 **`variable_study.py`는 모든 조건에 `dynamic_spin=True`를 넘기므로, 저장된
`variable_results/`의 모든 수치는 `magnus_physics.simulate`의 고정 시간간격(physics_dt)
적분으로 생성되었습니다.** 회전 상태 omega를 시간에 따라 적분해야 마그누스와 미끄러짐
전이를 다룰 수 있기 때문입니다. 등가속도 공식은 각 구간 끝에서 남은 거리를 맞추는
보조 역할만 합니다. 두 방식은 같은 물리를 쓰지만 이산화가 다르므로, 보고서에
"등가속도 공식으로 계산했다"고만 쓰면 부정확합니다.

이 때문에 `all_timestep_check.csv`의 physics_dt 수렴 검사가 필요하며, 실제로 dt를
1/4로 줄여도 개선량이 0.1151→0.1142초로 유지됩니다.

## 탐색과 공정성

이번 비교는 **사이클로이드를 공개된 초기 경로로 사용**하고 각 조건에서 더 좋은 경로를
탐색합니다. 이전의 직선 초기화와 다릅니다. 따라서 처음부터 정답 모양을 스스로 발견했다고
보고하면 안 됩니다. '기존 최단강하선을 초기값으로 하여 현실 조건에 맞게 수치 최적화'한
실험입니다. 사이클로이드가 불가능하면 직선 초기값으로 대체하며 불가능 결과는 빈칸/실패로
처리합니다.

학습 방식은 **엘리트 보존 진화전략((1+λ) ES)이며 신경망 PPO/SAC가 아닙니다.** Gymnasium
인터페이스는 1스텝 환경으로만 씁니다. 이동평균/스플라인/거칠기 벌점은 없습니다. 초기값을
포함한 최선 결과를 보존하므로 차이가 미미한 경우도 그대로 표시합니다.

`summary.csv`: 각 조건 내 시간 비교. `cross_evaluation.csv`: 모든 경로를 모든 조건에서
교차 평가한 값. 서로 다른 환경의 시간 차이는 환경 효과와 경로 효과가 섞이므로, 경로
개선을 말할 때는 `summary.csv`의 같은 행을 사용하세요. `settings.json`,
`case_parameters.json`: 실제 실행 설정. `all_timestep_check.csv`: 시간 간격 검사.

## Docker로 재현하기

컨테이너는 **화면 없이 전체 실험을 재현**하는 용도입니다(GUI 재생 창은 포함하지 않습니다).
이미지 빌드 중에 테스트 21개가 실행되며, 하나라도 실패하면 빌드가 중단됩니다.

```bash
# 빌드 (테스트가 함께 실행됨)
docker build -t brachistochrone-study:latest .

# 저장된 결과와 같은 설정으로 재실행, 산출물은 ./out에 남음
mkdir -p out
docker run --rm -v "$PWD/out:/app/out" brachistochrone-study:latest

# 테스트만 실행
docker run --rm brachistochrone-study:latest -m unittest -v test_project test_magnus

# 다른 설정으로 실행 (ENTRYPOINT가 python이므로 스크립트부터 적으면 됩니다)
docker run --rm -v "$PWD/out:/app/out" brachistochrone-study:latest \
  variable_study.py --episodes 50 --pop-size 10 --no-show --output-dir /app/out
```

docker compose도 됩니다.

```bash
docker compose run --rm study   # 전체 실험
docker compose run --rm tests   # 테스트만
```

재현성을 위해 `requirements.txt`는 버전을 고정했습니다
(gymnasium 1.4.0, numpy 2.5.4, matplotlib 3.11.2, Python 3.13).

컨테이너는 uid 1000으로 실행됩니다. 마운트한 `./out`에 쓰기 권한 오류가 나면
`--user "$(id -u):$(id -g)"`를 붙이세요.

## 재현 및 감사 결과

2026-11-13 전체 감사를 수행했습니다.

**확인된 사항**

- `python variable_study.py --episodes 180 --pop-size 20 --height 5 --length 10 --no-show`를
  재실행한 결과가 저장된 `summary.csv`, `cross_evaluation.csv`,
  `all_timestep_check.csv`와 **바이트 단위로 동일**합니다(seed 고정으로 완전 재현).
- 위 표의 모든 숫자가 `summary.csv`와 일치합니다.
- `04_rotation`의 √(1+k) 배율 주장이 1e−14 수준까지 성립합니다.
- 테스트 21개 전부 통과(기존 16개 + 이번에 추가한 회귀 테스트 5개).

**수정한 코드 결함**

1. `cycloid_curve()`가 중력을 10.0으로 하드코딩해, 중력을 바꾸면 반환되는 해석적 시간이
   시뮬레이션과 조용히 어긋났습니다(g=9.81에서 약 1%, g=1.62에서 약 150% 오차). `g`
   인자를 추가하고 모든 호출부에서 넘기도록 했습니다. 현재 설정은 g=10이라 **저장된
   결과에는 영향이 없습니다.**
2. 등가속도 경로(`simulate_physics`)가 실패할 때 `last_failure`를 설정하지 않아,
   `step()`의 `failure_reason`이 이전 호출의 값을 그대로 돌려줬습니다. 실패 원인을
   설정/초기화하도록 고쳤습니다.
3. `main()`에서 `ideal_time`이 for 루프 변수 누출에 의존해 참조됐습니다. 루프 앞에서
   초기화했습니다.
4. `requirements.txt`에 버전 고정이 없어 재현이 보장되지 않았습니다. 고정했습니다.

**수정한 문서 결함**

- "전체 조건에서 mu=0.15"는 모든 조건에 mu=0.15가 적용된다는 뜻으로 읽혔습니다. 실제로는
  `06_all`과 `02_friction`에만 적용되고 나머지는 0 또는 100입니다. 조건별 파라미터 표를
  추가했습니다.
- `01_radius`/`05_magnus`가 이상 조건과 겹치는 것을 "정상"이라고만 적어, 반지름과
  마그누스를 시험했으나 영향이 없다는 뜻으로 읽힐 수 있었습니다. mu=0·항력 off이면
  수직항력이 접선 운동에 들어갈 통로가 없어 **구조적으로 영향이 불가능**하다는 설명을
  추가했습니다.
- 저장된 결과가 `RESEARCH_PLAN_ORIGINAL.md`의 등가속도 공식이 아니라 고정 시간간격
  적분으로 생성됐다는 점이 문서에 없었습니다. 전용 절을 추가했습니다.
- 테스트 수(16 → 21)와 헤드리스 실행 방법을 갱신했습니다.

**연구계획서와 달라진 점(의도된 변경)**

`RESEARCH_PLAN_ORIGINAL.md`는 H=0.5m, L=1.0m, m=50g, 꽉 찬 구 k=0.4를 전제하고 3D 프린팅
실증을 목표로 합니다. 이 연구는 효과를 관찰하려고 H=5m, L=10m, m=2.7g, 속 빈 구 k=2/3으로
바꾼 **시뮬레이션 단독** 단계입니다. 3D 프린팅 실증은 수행하지 않았습니다. 계획서의 조작변인
가운데 마찰 계수와 회전 고려 여부는 반영됐지만, **반지름을 조작변인으로 여러 값에 대해
비교한 부분은 아직 없습니다**(현재는 0과 0.02m의 on/off 두 가지뿐).

## 시각화/검증/한계

기존 배속, 세대 슬라이더, Race/Evolution, 회전 상태/마그누스 힘/수직항력 표시를
유지했습니다. 각 조건 폴더에는 rotation 또는 no_rotation 스냅샷 하나만 있으므로 그 조건만
재생됩니다. 창의 회전 라벨은 저장파일 분류이며 구체적인 물리 조건은 폴더명과 위의
파라미터 표를 기준으로 확인하세요.

검증하지 않은 것: 실제 데스크톱 마우스 조작, **공간 격자(구간 수) 수렴**, 여러 시드에 대한
통계적 우월성, 실험 측정값, 3D 프린팅 실증.

유한차분 곡률과 구간별 직선 경로를 결합한 근사 모델이며 실제 질량중심 오프셋 전체는
계산하지 않습니다. 마그누스 양력 계수는 미보정 가정값입니다. 구름저항/공력 회전 감쇠/
바람/3D/비행·재착지는 없습니다. 접촉 이탈은 실패입니다. 실제 트랙 제작 전 기하학·마찰·
양력 계수 검증이 필요합니다.

더 작은 트랙에서 차이가 줄어들면 그 또한 물리적 결과입니다. 실제로 계획서 크기
(H=0.5m, L=1m)로 되돌려 실행하면 `06_all` 개선율이 3.92%에서 **0.08% 수준으로
떨어집니다**(동일 탐색 예산 기준). 큰 시뮬레이션 트랙에서의 개선을 작은 3D 프린팅 장치에
그대로 적용한다고 주장하지 마세요.
